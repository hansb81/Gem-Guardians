# Gem Guardians 밸런스 시뮬레이션 (Claude Code에서 돌리는 테스트)

작성 2026-11-05 · 레포 위치: `docs/simulation.md` · 설정: `config/sim.json`
목적: 실제 게임 코드(퍼즐 코어 + 전투 코어)를 화면 없이 빠르게 돌려서 "레벨 없이 몇 층까지 가나", "골드·레벨업이 맞나", "나중 잼 특수 효과가 얼마나 세질까"를 숫자로 본다. 결과 요약을 이 프로젝트에 붙여 주면 그걸 보고 `balance.json`을 다시 맞춘다.

## 1. 구조
- `tools/sim/` (Node로 실행, 브라우저 API 없음). 게임의 `src/core`(보드·매치·특수 잼·방해요소·전투·경제)를 **그대로 import**해서 쓴다. 시뮬레이션용으로 규칙을 따로 짜지 않는다 → 게임과 결과가 어긋나지 않음.
- 시간: 고정 dt(0.05초)로 `update(dt)`를 돌린다. 애니메이션 대기는 `secondsPerMove`에 포함된 것으로 본다.
- **봇 플레이어**: 매 `secondsPerMove`초마다 보드에서 가능한 스왑을 모두 찾아 점수를 매기고 고른다.
  - 점수 = 그 스왑으로 지워지는 잼 수(연쇄 포함, 실제로 보드 복사본에서 돌려 봄) + 특수 잼 생성 보너스 + (bombAware면) 시한폭탄 해제 보너스 + 성벽에 가까운 적이 있을 때 그 색 탑 우선.
  - `best` / `top3` / `random` 세 가지 성향(sim.json `players`).
- 난수는 시드 고정. 같은 명령은 언제나 같은 결과.
- 실행: `node tools/sim/run.js --test=T1 --player=normal --seeds=5 --floors=1-100` 처럼. 결과는 `reports/sim/<테스트>_<날짜>.csv`와 `reports/sim/summary.md`.

## 2. 테스트

### T1. 레벨 없이 어디까지 가나
- 탑 5개 모두 Lv1(그리고 비교용 Lv10, Lv20 고정)으로 1층부터 올라가며, 시드 5개 중 3개 이상 실패하는 첫 층에서 멈춘다.
- 플레이어 3종 × 레벨 3종 표.
- 보는 값: 최대 층, 층별 클리어 시 성벽 남은 비율, 층 시간, 실패 원인(적 누적 / 시한폭탄 / 보스).
- 기준(sim.json `targets.noLevelReach`): 보통 15~25층, 캐주얼 8~15층. **이보다 높으면 "너무 쉬움"** → `hpGrowth`나 `threatBudget`을 올린다.

### T2. 잼 특수 효과 미리 시험 (아직 개발 전)
- 피해 계산 파이프라인에 **가상 효과(modifier) 훅**을 둔다: `onShot(shot) → shot`(피해 배율, 연타), `onHit(enemy, dmg)`(도트, 둔화, 범위, 관통, 연쇄). 지금은 시뮬레이션에서만 켜지만, 나중에 실제 스킬도 같은 훅에 붙이도록 만든다.
- sim.json `modifiers`의 효과를 하나씩 켜고 T1과 T4를 다시 돌린다.
  - dmg+20%, 5발마다 3배(폭발적 피해), 특수 잼 사격 2배, 빨강 도트(피해 50%를 3초), 파랑 둔화(속도 ×0.6, 2초), 특수 잼 범위(주변 50%), 파랑 관통 2마리, 노랑 연쇄 2번, 그리고 기본 4종 동시(`allBasic`).
- 보는 값: **등가 전력** = 효과 없이 같은 최대 층(T1)이나 같은 클리어 시간을 내려면 공격력이 몇 배 필요한가. 예: "관통2 = 공격력 ×1.4와 같음".
- 이 표로 나중 스킬·아이템에 쓸 수 있는 힘의 크기를 정하고, 그만큼 `hpGrowth`를 조여 둘지 결정한다.
- 미리 알려진 점: 웨이브가 없어서 후반은 HP보다 **처리 속도**(퍼즐 한 번에 1~2마리)가 벽이다. 그래서 범위·관통·연쇄가 단순 피해 증가보다 훨씬 셀 가능성이 높다. T2로 확인.

### T3. 플레이에 따른 골드
- 층마다: 처음 클리어 골드, 다시 깬 골드(×0.3 보너스), 실패 시 골드(잡은 만큼).
- 분당 골드 = 골드 ÷ 층 시간. 같은 층을 반복할 때(파밍) 분당 골드도 따로.
- 보는 값: 첫 클리어 한 번에 탑 레벨 몇 개를 살 수 있나(`targets.levelsPerFirstClear` 0.6~1.5), 파밍 분당 골드가 다음 층 첫 클리어보다 너무 좋지 않은지(좋으면 파밍만 하게 됨).

### T4. 레벨업에 필요한 재화 (진행 시뮬레이션)
- 1층부터 실제 진행처럼: 층 도전 → 실패하면 가진 골드로 레벨업(`levelStrategies`: even / byUse) → 다시 도전 → 클리어하면 다음 층. 100층(또는 실패 10번 연속)까지.
- 보는 값: 층별 도전 횟수, 레벨업에 쓴 골드 누적, 층에 들어갈 때 평균 탑 레벨, 100층까지 총 플레이 시간.
- 기준: 일반층 다시 하기 0~1번, 보스층 1~3번, **4번 이상이면 "벽"** 표시. 100층까지 보통 플레이어 5~10시간(`minutesTo100`).
- byUse가 even보다 훨씬 좋으면 "많이 쓰는 색만 올리는 게 정답"이 된다 → 색별 차이를 만들지(업그레이드 단계) 판단 자료.

### T2-실제. 실제 기술 측정 (v9)
- 가상 modifier 대신 `config/skills.json`의 실제 색 효과·특수 잼 기술을 켜고 끈다: 없음 / 색 효과만 / 특수 잼 기술만 / 전부 / 전부+보스 면역·약점.
- 보는 값: 고정 보스층(10~100) needPower, 각 효과 발동 횟수와 피해 합계, 전체 피해 중 기술 몫(%), 상태효과가 막은 성벽 피해(경직·감속·넉백).

### T6. 장착 아이템
- 아이템 봇 정책(규칙 기반): 수리 망치 = 성벽 40% 아래, 모래시계 = 보스가 성벽 0.2 안 또는 성벽 50% 아래, 낫 = 특수 잼·시한폭탄이 가장 많은 줄, 망치 = 시한폭탄 2 이하 잼 > 특수 잼 만들기 한 칸, 무지개 결정 = 보스층에서만, 교환 장갑 = 특수 잼 둘을 붙일 수 있을 때.
- 구매 정책: none / boss(보스 직전 층에서 골드의 15%까지 사서 보스에 씀) / always(장착 3~4칸 항상 채움). 보스 첫 클리어 보상 아이템 2개 포함.
- 보는 값: 보스 재도전 차이, 아이템에 쓴 골드 비율, 100층 시간 차이, 아이템별 사용 횟수.

### T7. 운의 폭 (기준 v11, 2026-11-07 갱신)
- 보스층마다 시드 30개(31~60). 기준 레벨 = 그 플레이어의 **T4 실제 진입 레벨**(해금 골드 등 실제 비용을 낸 뒤의 레벨), 그리고 +2, +4, 아이템(boss 정책).
- 목표 (sim.json targets.luck과 같음):
  - normal: 기준 레벨 승률 60~75% (10층만 75~85%), +2 ≥ 75%, +4 ≥ 85%, 아이템 ≥ 85%
  - slow: 기준 레벨 40~70%, +4 ≥ 75%
  - 같은 레벨 클리어 시간 P90/P10 ≤ 1.8
- 운이 너무 크게 갈리면 줄이는 장치를 따로 정한다: 특수 잼 보정 확률, 매치 적은 보드 재배치 등.

### 기술 해금 일정 옵션 (2026-11-07)
- `--skills=shop | shop-free | none | color | special | all | all+boss`, **기본값 `shop`**.
  - `shop`: 해금 A안 + 해금 골드 차감(실제 게임과 같음). 가시는 처음부터 Lv 1, 용암탄·영혼 불꽃·궁극기(+대폭발)는 10·20·30층 보스를 처음 잡은 뒤(최고 층 > 그 보스층) 해금할 수 있다.
  - `shop-free`: 같은 해금 일정, 골드는 내지 않음(조건이 풀리면 바로 Lv 1).
  - `all+boss`: 전부 처음부터 열림 + 보스 면역·약점(v9/v11 기준, 비교용). `none/color/special/all`은 T2s 비교용.
  - 레벨은 전부 Lv 1(색 효과 레벨업·아이템 구매 없음). 해금 규칙·가격은 게임 코드(`src/core/shop/shop.js` `applySkillLevels`/`buildRail`, `config/shop.json`)를 그대로 불러 쓴다.
- 해금 비용 처리(`shop`): 해금가 = round(`skills.special.<id>.unlockGold` × 최고 층 기준 일반 층 보상(`economy.normalFloorReward`)).
  - 진행 테스트(T4, 그리고 T4를 쓰는 T3 레벨·T5 민감도·T7 slow 기준 레벨): 매 도전 전과 레벨업 직전에 확인해 골드가 모이면 바로 산다. 해금할 기술이 남아 있으면 탑 레벨업보다 먼저(그동안 레벨업 안 함), 사기 전엔 잠긴 채로 싸운다.
  - 고정 층 테스트(T1, T2, T7 공격)는 조건(최고 층 > 보스층)만 본다 - 해금은 모두 다음 보스 전에 끝나서 보스층 상태가 같다.
  - 따로 비용 플래그는 없다: 비용 있음 = `shop`, 없음 = `shop-free`.
  - 구현 차이(2026-11-07): 위 T7 기준("T4 실제 진입 레벨")과 달리 지금 시뮬은 normal 기준 레벨을 해금 골드를 모르는 `expTowerLevel`로 잡는다(slow는 이미 T4 진입 레벨). 다음 재실행에서 normal도 T4 진입 레벨로 바꾼다.
- `--set=경로=숫자;경로=숫자`: `balance.json`을 메모리에서만 덮어쓴다(파일은 그대로, 숫자만, 없는 경로는 에러). summary 헤더에 "메모리 덮어쓰기(--set ...)"로 남는다. 예: `"--set=floorShape.bossMul.hpMulByFloor.10=0.82;scaling.enemyHpMul=1.6"`. HP 배율(`enemyHpMul`, `hpMulByFloor`)은 바로 반영되지만, `floors.json`에 미리 계산된 값(`hpGrowth` 등)은 1~100층에 반영되지 않는다(`tools/gen_floors.py` 다시 돌려야 함).
- 새 리포트 항목(`--skills=shop`일 때 T4):
  - summary.md 표 `### T4 특수 기술 해금 (A안, 해금 골드 차감 - 층 = 산 시점의 최고 층, 시드 평균 (최소~최대))`: `플레이어:전략 | lava 해금 층 | soul 해금 층 | ult 해금 층 | 해금 골드 / 전체 획득 골드`.
  - CSV `reports/sim/<out>/t4_<날짜>.csv`의 `section=unlock` 행: `player, strategy, section, unlock_<id>_avgFloor, unlock_<id>_minFloor, unlock_<id>_maxFloor, unlock_<id>_missingSeeds, unlockGoldShare` (`<id>` = lava/soul/ult, missingSeeds = 100층 안에 못 산 시드 수).
  - T3 "첫 클리어로 살 수 있는 레벨"은 해금 골드를 빼지 않은 값이다.

### T5. 추가로 볼 것 (제가 판단해 넣은 것)
- **방해요소 영향**: 같은 층을 방해요소 켬/끔으로 비교. 퍼즐 효율(스왑당 지운 잼) 몇 % 줄었나, 시한폭탄이 몇 번 터졌나. 시한폭탄 피해가 성벽 피해의 30%를 넘으면 과함.
- **적 역할별 위험도**: 성벽 피해를 준 적을 역할별로 합산. 한 역할(예: 돌격·떼)이 대부분이면 그 역할 스탯을 조정.
- **보스 처치 시간**: 보스가 성벽에 닿기 전에 잡는 비율. 닿고 나서 잡는 게 보통이면 보스가 너무 단단함.
- **색 편중**: 봇이 지운 잼의 색 비율. 특정 색이 많으면 퍼즐 생성 확률 문제.
- **연쇄·특수 잼 빈도**: 스왑당 평균 잼 수, 연쇄 수, 특수 잼 생성률. 이 값으로 `balance.json` `playerModel`(파이썬 모델의 가정)을 실제 값으로 고친다.
- **민감도 표**: `hpGrowth`, `threatBudget.perFloor`, `spawnInterval.min`, `levelCost.growth`를 ±10% 바꿔 T1·T4 결과가 얼마나 움직이는지. 어떤 손잡이가 제일 센지 알 수 있다.

## 3. 결과 요약 (summary.md) 형식
```
## T1 레벨 없이
| 플레이어 | Lv1 | Lv10 | Lv20 |   (최대 층)
## T2 효과별 등가 전력
| 효과 | 최대 층(Lv1) | 등가 공격력 배율 |
## T3 골드
| 구간 | 첫 클리어 골드 | 층 시간(초) | 분당 골드 | 첫 클리어로 살 수 있는 레벨 |
## T4 진행
| 구간 | 평균 도전 횟수 | 진입 시 평균 Lv | 누적 시간(분) | 벽 층 |
## T5
방해요소 영향, 역할별 성벽 피해 비율, 보스 처치 비율, 색 비율, 스왑당 잼/연쇄/특수 잼
## 기준 벗어남
- 너무 쉬움: ... / 너무 어려움: ... / 벽: ...
```
이 summary.md 내용을 그대로 붙여 주면 다음 밸런스 조정에 쓴다.

## 4. 참고: 파이썬 모델 값 (게임 코드 아님)
`tools/sim_floors.py`(가정 기반 대략 모델)로 미리 본 값. 실제 게임 시뮬레이션과 비교용.
- 레벨 없이(v6): 빠른(1.8초) 19층, 보통(2.5초) 9층, 느린(3.5초) 9층. 10층 보스에서 1차로 막히는 것이 목표(보스 = 관문). 실제 봇은 이 모델보다 약 1.6배 세게 나왔으므로(v5 결과) v6에서 보정함.
- 기대 레벨로 갈 때 필요 전력: 일반층 0.23(1~10) → 0.91(91~100), 보스 0.75~1.0. 자세한 값은 `balance.md` 9장.
