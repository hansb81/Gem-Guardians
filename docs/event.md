## 1. 두 방식 비교

| | A. 배너를 누르면 바로 지급 | B. 새 전용 팝업에서 받기 |
|---|---|---|
| 좋은 점 | 한 번 탭으로 끝 | 눈에 잘 띔, 보상·기간 설명 자리 넉넉 |
| 문제 | 무엇을 받는지·기간을 보여 줄 자리가 없음. 목록을 스크롤하다 잘못 눌러도 지급됨. **이벤트 팝업 아래 광고 칸 바로 위에 "누르면 보상" 요소** → AdMob 오클릭 유도로 보일 위험(ads 계획: 광고 근처에 보상처럼 보이는 것 두지 않기) | 이벤트 버튼은 여전히 빈 팝업으로 남고, 이벤트마다 팝업을 새로 만들어야 함 |

## 2. 추천: 둘을 합친 "목록 → 상세" 방식

```
메뉴 [이벤트] (빨간 점) ─▶ 이벤트 팝업(목록, 아래 광고 칸)
                              │ 배너 탭
                              ▼
                       이벤트 상세 팝업 (광고 없음)
                       배너 · 설명 · 보상 칸 · 기간 · [받기]
                              │ 서버 판정 (계정당 1번)
                              ▼
                       공통 획득 팝업 → 목록 배너에 "받음" 도장
```

- **이벤트 팝업 = 배너 목록.** 이미 코드에 있는 목록(`mainMenuScreen.events`, 줄 472×110, 스크롤, 아래 광고 칸)에 배너 그림만 얹는다. 앞으로 이벤트가 늘어도 줄만 추가.
- **보상은 상세 팝업의 [받기] 버튼으로만.** 광고 칸과 떨어진 별도 팝업이라 AdMob 문제 없음(광고는 목록 팝업에서만 뜸, `syncPopupBanner`가 `popup === 'event'`일 때만 띄우므로 자동으로 숨음).
- **눈에 띄게:** 받을 수 있는 이벤트가 있으면 메뉴 이벤트 버튼에 빨간 점 + 배너 오른쪽 위 점. 이벤트마다 **기기당 처음 한 번 상세 팝업 자동 열기**(튜토리얼 끝난 뒤, 출석 자동 팝업이 닫힌 다음 차례).
- **지급 = 서버 판정 + 바로 지급**(쿠폰과 똑같은 길). 우편으로 보내는 것보다 탭이 적고, 서버가 `claims`에 `event:{id}`로 기록하므로 계정당 1번이 보장된다. 지급하다 끊겨도 다음 실행 때 `claims-pending`으로 다시 들어온다.

## 3. 서버 (Supabase `jzpjqfbpqzghprqbqexp`, Routory에는 절대 X)

- 이미 있는 `events` 표(s1_core)를 넓힌다: `bundle jsonb`, `banner text`(그림 키), `body_ko/en`, `platforms text[]`(null = 전부), `sort int`, `kind text default 'claim'`(나중에 `notice` = 받기 없는 안내).
- RPC `event_claim(player, event_id)`: banned → notFound(없음/꺼짐) → notStarted → expired → platform → already(`claims`에 `event:{id}`) → claims 기록(kind `event`) → `{ok, txId, bundle, title}`.
- 목록은 `hello` 시작 정보에 `events`로 같이 준다(통신 한 번 아낌) + 이벤트 팝업 열 때 `event-list`로 새로고침. 각 줄에 `claimed` 표시.
- 운영: 쑹이 SQL 편집기에서 `event_create(...)`로 **꺼진 상태로 미리 등록** → 출시 때 `event_set_enabled('launch2026', true)`로 켬, false로 끔. 배포 없이 기간·보상 수정 가능.

## 4. 보상과 기간 (제안)

| 보상 | 수량 | 이유 |
|---|---|---|
| 다이아 | 100 | 출석 1주(95)와 비슷. 스타터 팩(1,200원, 다이아 300 + 아이템)보다 작아서 첫 결제를 깎아 먹지 않음 |
| 망치 | 3 | 초반 막힐 때 바로 써 볼 수 있는 아이템 |
| 낫 | 3 | 새로 합친 낫 홍보 |
| 부활 깃털 | 1 | "한 번 살려 주는" 경험 → 나중에 깃털 구매 동기 |
| 정령석 | 10 | 정령 시스템 맛보기(출석 1주 분량) |

- 크게 가고 싶으면 다이아 300까지 올려도 되지만, 그러면 스타터 팩 다이아와 같아진다.
- **기간: 정식 출시일 00:00 ~ 2026-12-31 23:59:59 (KST)** (쑹 2026-11-28 확정). 출시일이 정해지면 그때 SQL로 등록(앱 업데이트 필요 없음). 기간 안에 새로 시작한 사람도 받는다.
- 문구: 제목 "출시 기념 선물" / "Launch Gift", 설명 "Gem Guardians 정식 출시를 기념해 모든 수호자에게 선물을 드려요!" / "To celebrate the launch of Gem Guardians, here's a gift for every guardian!"

## 6. 알아 둘 점

- **재설치 = 새 게스트 계정** → 다시 받을 수 있음(쿠폰과 같은 한계). 보상이 작아서 감수. Google 계정 연결한 사람은 같은 계정이라 다시 못 받음.
- 서버가 꺼진 빌드(웹 등)는 목록이 비어 지금처럼 "새 이벤트를 준비하고 있어요".
- 토스·iOS도 같은 방식으로 문제없음(코드 입력이 아니라 앱 안 보상). 특정 마켓만 하려면 `platforms`.

## 7. 앱 업데이트 없이 이벤트 추가 (2026-11-28 쑹 요청)

- 이번 한 번 앱을 고치면, 그 뒤로는 **관리자 페이지 이벤트 탭**에서 추가·수정·켜기/끄기 → 다음 실행(또는 이벤트 팝업 열 때)에 게임에 뜬다.
- 서버에서 오는 것: 제목·설명(ko/en), 보상, 기간, 순서, 마켓, 켜기/끄기, **배너 그림**(Supabase Storage 공개 버킷 `event-banners`, 236×55 PNG 업로드).
- 앱에 든 것: 출시 배너, 기본 배너(그림 못 받으면 대신), 받음 도장.
- 앱 수정이 필요한 것: 새 **종류**의 이벤트(7일 로그인, 미션 등). 지금 종류는 `claim`(1회 보상)과 `notice`(안내만).
