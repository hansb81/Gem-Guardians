## 3. 문서와 코드가 아직 안 맞는 부분 (구현 TODO)
- **패키지 환산표**(refund-policy 제4조, 2026-11-27): 아이템 다이아 가치 = `config/items.json` goldBase × 20(`config/shop.json` goldex 소 = 다이아 20 / 층 보상 1개), 다이아 아이템 = items.json `diamond`, 4번째 슬롯 = shop.json `slot4Dia`, 광고 제거 = 결제 금액 − 쓴 다이아 × 20원(products.json dia.0 = 1,200원 / 60개). **이 값이나 패키지 구성(products.json)을 바꾸면 환산표(ko·en, md·html)도 같이 고친다.**
- **환불 회수**: 수동 대응(2026-11-27 쑹 결정). 코드는 환불 시 adFree만 자동 회수(platform-plan §15). 약관은 "회수할 수 있다"는 권리 조항이라 나머지는 환불 주문을 보고 반복하는 계정만 직접 제재. 자동 회수(서버 `refunded` 주문을 `refund:{orderId}` tx로 번들 차감, 0 밑으로 안 감)는 v2 - 원스토어·토스 환불 조회를 붙일 때 같이.
- **"사용하지 않음" 판정**: 지갑이 로컬이고 유료/무료 다이아가 구분되지 않아서, 지금은 "그 결제로 받은 수량 이상이 남아 있고 구성 아이템이 그대로인지"로 수작업 판단. 관리자 페이지 결제 화면에 해당 플레이어 클라우드 저장 요약(다이아·아이템 수)을 같이 보여 주면 판단이 빨라짐. 장기적으로 유료 다이아 별도 집계(`diaPaid`) 권장.
- **원스토어 빌드**: 다른 마켓 이름/링크 금지 → 환불 팝업에서 해당 마켓 줄만.
- 확률형(정령석 가챠 등)을 넣으면 약관 제16조대로 확률 표시 페이지 필요.
- 개인정보 처리방침은 별도 문서 필요(이번 범위 밖). 결제 기록 5년 보관, Supabase/RevenueCat 국외 이전 고지 포함.
