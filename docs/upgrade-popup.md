## 0. 한 줄 요약

지금 따로 있는 **탑 강화 팝업(340x480)** 과 **보관함 팝업(거의 전체 화면)** 을 하나로 합친다.
크기는 보관함 기준, 탭은 `석상 / 토템(잠김) / 보관함` 3개. 층 클리어 후, 패배 후, 마을(메뉴 받침대)에서
모두 **같은 팝업 한 개**를 열고, 상황(context)에 따라 제목·아래 버튼·기본 탭만 바뀐다.

---

## 1. 크기와 틀

| 항목 | 값 (540x960 화면 px 기준) |
|---|---|
| 팝업 사각형 | x 12, y 96, w 516, h 816 (좌우 12, 위 96, 아래 48 여백 = 지금 보관함과 같음) |
| 틀 | `ui/menu/popup_menu` 9-slice 16, 2배 |
| 엠블럼 | `upgrade/emblem_upgrade` (위 변 가운데). 보관함 전용 엠블럼은 만들지 않고 이 하나로 통일 |
| 뒤 덮개 | 지금 다른 팝업과 같은 방식(코드 채우기). 시안은 체커 디더로 그림 |
| 위치 값 | `config/hud.js`의 `popup.sheet = { marginX: 12, top: 96, bottom: 48 }` 한 곳에서만 정함 |

화면 비율이 달라도(긴 폰) 같은 여백 규칙을 쓰고, 안쪽 목록만 늘어나거나 스크롤된다.

## 2. 위에서 아래로 구성 (모든 탭 공통)

```
        [엠블럼]
   ┌──── 제목 (상황별) ────────── [X]* ┐
   │ 상황 글자(회색)        [● 520 골드] │  ← 골드는 모든 탭에서 보임
   │ [ 석상 ][ 🔒토템 ][ 보관함 ]        │  ← 탭 3개 (upgrade/tab_on·off)
   │ ┌ 탭 본문 (upgrade/tab_body) ─────┐ │
   │ │                                │ │
   │ └────────────────────────────────┘ │
   │ [ 아래 행동 버튼 (상황별) ]          │
   └────────────────────────────────────┘
   * X는 마을에서만
```

### 상황별 차이

| 상황 | 제목 | 상황 글자 | 처음 열리는 탭 | 아래 버튼 | X |
|---|---|---|---|---|---|
| 층 클리어 후 | `11층 클리어` | 다음 층 준비 | 석상 | `12층으로 ▶` (금색, 가로 전체) | 없음 |
| 패배 후 | `11층 실패` | 재도전 준비 | 석상 | `마을로`(회색) + `11층 재도전`(보라) | 없음 |
| 마을 (받침대 → 보관함) | `정비` | 최고 기록 18층 | **보관함** | 없음 (본문이 그만큼 길어짐) | 있음 |
| (있다면) 전투 중 석상 탭 | `정비` | 일시정지 | 석상 + 누른 석상 줄 금테 | 없음 | 있음 = 닫고 계속 |

- 층 클리어/패배에서는 X를 없앤다. 나가는 길이 아래 버튼 하나뿐이라 "X를 누르면 어디로 가나?"가 생기지 않는다.
- 탭은 같은 판 안에서는 마지막에 본 탭을 기억(층 클리어 → 보관함 봤으면 다음 층 클리어에도 보관함). 앱을 다시 켜면 석상.
- 마을에서는 항상 보관함 탭으로 연다(받침대 이름이 "보관함"이므로).

## 3. 석상 탭 (기존 레벨업 탭 재배치)

팝업이 넓어지고(170 → 258 원본 px) 높아져서 한 줄에 정보를 더 넣는다. 5줄 고정, 스크롤 없음.

```
┌──────────────────────────────────────────────┐
│ ┌────┐ 루비 모아이                 [◆ 61   ] │ ← 강화(골드 버튼, 1레벨)
│ │석상│ [Lv24] +1                   [MAX +6 ] │ ← MAX(보라, 지금 골드로 올릴 수 있는 레벨 수)
│ │2배 │ 공격 412 › 498                        │
│ └────┘                                       │
└──────────────────────────────────────────────┘ × 5
 길게 누르면 연속 강화              전체 공격 1537
```

| 바뀐 점 | 이유 |
|---|---|
| 아이콘 → **석상 그림 2배(32x40)** 를 받침 상자(`ui/menu/inset`) 안에 | 넓어진 자리를 가장 알아보기 쉬운 정보에 씀. 마을에는 전투 화면이 없어서 "어느 석상인지"를 팝업 안에서 보여 줘야 함 |
| 3줄: 이름 / Lv 배지 / 공격 현재 › 다음(초록 숫자) | 이름이 길어도(사파이어 포세이돈 9자) 버튼과 안 겹침 |
| 버튼을 **세로로** 쌓음: 강화(위, 22 높이) + `MAX +N`(아래, 18) | 가로 배치는 이름 자리를 먹음. `+N`으로 MAX가 몇 레벨인지 미리 보임 |
| 강화 피드백을 **줄 안에서**: 줄이 금테가 되고 Lv 옆에 초록 `+1`이 떴다 사라짐, 석상이 1프레임 흰 테 | 마을에서는 전투 화면의 석상 효과(triggerTowerTapFx)가 안 보이므로 팝업 안에서 보여 줌. 전투 화면에서는 기존 효과도 같이 |
| 골드 부족: 버튼 `btn_disabled`, 비용 숫자 빨강 + 검은 바탕, MAX는 `MAX`만 | 지금과 같음 |
| 최대 레벨: 강화 버튼 자리에 `MAX` 글자, 두 버튼 모두 비활성 | 지금과 같음 |
| 아래 줄: 왼쪽 "길게 누르면 연속 강화", 오른쪽 "전체 공격 합" | 보유 골드는 위 상황 줄로 옮김(모든 탭 공통) |

조작은 그대로: 강화 탭 = 1레벨, 누르고 있으면 연속(가속), MAX = 살 수 있는 만큼.
석상 레벨은 저장값(`playerState.towerLevels`)이라 **마을에서도 강화 가능**, 다음 판부터 적용.

## 4. 토템 탭 (잠김)

- 탭 버튼: 자물쇠 아이콘 + 흐린 글자 `토템`. **누를 수는 있고**, 누르면 잠긴 안내 화면을 보여 준다(토스트만 띄우는 것보다 "무엇이 생길지" 보임).
- 본문: 석상 5줄(실루엣 #3b3347 + 흐린 이름) × 토템 칸 2개(`slot_locked`) + 아래 안내판(자물쇠 2배, `토템 · 준비 중`, 설명 2줄, `열리는 조건: 추후 공개`).
- 데이터: 인벤토리 기획 6장 그대로 `perm.totems {}`, `loadout.totems` 빈 값. 로직 없음.
- 잠금은 `config/hud.js`(또는 features 설정) `totemTab.locked = true` 하나로. 나중에 false로 바꾸고 본문만 채우면 된다.
- 토템 그림·이름은 아직 없음. 시안의 줄/칸 배치는 자리 표시용.

## 5. 보관함 탭

보관함 시안 B(`plan/inventory/prompt-claude-code-vault-ui.md`)를 **그대로** 탭 안으로 옮긴다.
위에서 아래: 장착 칸 → 다음 층 예약 → 분류 탭(전체/보드/전투/기타) → 보유 칸 5열(스크롤) → 고정 설명 패널.

| 바뀐 점 | 내용 |
|---|---|
| 높이 | 위에 제목·상황 줄·탭 줄(약 60 원본 px)이 생겨서 보유 칸이 **2줄 반**(층 클리어/패배) / **3줄**(마을, 아래 버튼 없음) 보임. 반 줄이 잘려 보여서 스크롤이 있다는 걸 알 수 있음 |
| 설명 패널 버튼 | 높이 16(원본)으로 낮춤. 나머지 규칙은 시안 B 그대로 (장착/해제/상점에서 사기 + 상점 가기) |
| 층 진행 중 표시 | 패배 후에는 장착 칸 오른쪽 보조 글자가 파란 `다음 층부터 적용`, pending과 다른 칸은 `slot_selected` (기존 규칙 §8-10 그대로) |
| 층 클리어 후 | 층과 층 사이라 바로 다음 층에 들어감 → 보조 글자는 `n/3 · 길게 누르면 해제` |
| 마을 | 즉시 장착 (기존 규칙 그대로) |
| 이름 길이 | 장착·예약 칸 이름은 칸 간격(장착 56, 예약 75 원본 px)을 넘으면 말줄임 |
| 상점 가기 | 층 클리어/패배에서 누르면 상점을 이 팝업 **위에** 열고, 닫으면 이 팝업으로 돌아옴. 마을에서는 지금처럼 상점 화면 |

### 패배 팝업과의 관계
- 부활(불사조 깃털)은 지금처럼 **패배 직후 작은 패배 팝업**에서 처리. 부활 안 하면 → 이 통합 팝업(패배 상황).
- 패배 팝업에 있던 "다음 층 예약 줄"은 **삭제**하고 통합 팝업 보관함 탭 하나로 모은다(같은 걸 두 곳에서 바꾸지 않게).

## 6. 흐름

```
층 클리어 ─ 승리 연출/보상 ─▶ [통합 팝업: 층 클리어] ─ 12층으로 ▶ ─▶ 다음 층(보드 유지)
패배 ─ [패배 팝업: 부활?] ─ 아니오 ─▶ [통합 팝업: 패배] ─ 재도전 ─▶ 같은 층 새 보드
                                                   └─ 마을로 ─▶ 메인 메뉴
메인 메뉴 받침대(보관함) ─▶ [통합 팝업: 마을, 보관함 탭] ─ X ─▶ 메뉴
```
기존 동작(다음 층 = 보드 유지, 재도전 = 새 보드 + 섞기 연출)은 바꾸지 않는다.

## 7. 코드 구조 (제안)

- 새 모듈 `src/render/ui/prepPopup.js` (이름은 쑹 코드에 맞춰도 됨)
  - `layoutPrepPopup(screenW, screenH, context, tab)` → 모든 사각형(틀, 탭, 본문, 줄, 버튼, 칸)을 돌려주는 **순수 함수** (테스트 가능)
  - `drawPrepPopup(ctx, assets, state, layout)` → 그리기만
  - `hitPrepPopup(layout, x, y)` → `{ type: 'tab'|'upgrade'|'max'|'slot'|'item'|'filter'|'reserve'|'action'|'close', ... }`
- 상태: `{ context: 'floorClear'|'defeat'|'village'|'towerTap', tab: 'statue'|'totem'|'vault', selectedTower, vault: { filter, selectedItem, scrollY } }`
- 전투 화면(canvasRenderer)과 메인 메뉴(mainMenuScreen) **둘 다** 이 모듈만 부른다. 기존 `_drawTowerUpgradePopup` / `_drawTowerUpgradeLevelTab` / `_drawTowerUpgradeInventoryTab` 와 메뉴 쪽 보관함 팝업 그리기는 지운다.
- 강화 로직은 그대로 `playerState.tryLevelUpTower / levelUpTowerMax`, 연속 강화도 기존 `upgradeHold` 재사용. 인벤토리는 기존 inventory 모듈 API만.
- 탭 키 이름 변경: `levelUp → statue`, `inventory → vault`, `totem` 추가. 문구 키 `popup.prep.*` (ko/en).
