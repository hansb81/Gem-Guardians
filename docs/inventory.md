## 0. 한 줄 요약

**"플레이어가 가진 것"을 한 모듈(`inventory`)이 전부 관리한다.** 상점, 보스 보상, 패스, 임시 지급, 개발 패널 모두 같은 `grant()` 한 함수로 넣고, 아이템 사용·예약 소모는 `spend()`로 뺀다. 가방 그리드 같은 복잡한 UI는 만들지 않고, 지금 있는 **탑 강화 팝업의 인벤토리 탭**을 장착·예약 화면으로 쓴다.

왜 필요한가: 아이템 코드(`items`, `equipped`)와 상점 코드(`shop.skillLv`, 패키지 지급)가 각자 playerState에 필드를 늘리고 있어서, 이대로 가면 "보유 수를 바꾸는 곳"이 여러 군데가 된다. 지급 경로가 여러 개면 중복 지급, 저장 누락, 결제 후 미지급 같은 버그가 생기기 쉽다.

## 1. 무엇을 담나 (3종류)

| 구분 | 예 | 성질 | 저장 위치 |
|---|---|---|---|
| **소모품** | 아이템 16종(망치~부활) | 개수. 쓰면 줄어든다 | `inv.items { id: 개수 }` |
| **장착·예약** | 하단 슬롯 3~4칸, 다음 층 예약(부스터 2종·황금 주화), 토템 슬롯(나중) | 무엇을 어디에 꽂았나. 개수는 소모품 쪽 | `inv.loadout` |
| **영구 보유** | 젬 스킬 해금·레벨, 4번째 슬롯, 광고 제거, 토템(나중) | 한 번 얻으면 안 사라짐 | `inv.perm` |

**인벤토리가 아닌 것**
- 골드·다이아 = 지갑(`playerState.gold/diamonds`) 그대로. 단, 지급 묶음(번들)에는 골드·다이아도 들어갈 수 있고 `grant()`가 지갑에 넣어 준다.
- 탑 레벨 = 진행도(`towerLevels`) 그대로. 상점 상품이 아니므로 인벤토리 밖.
- 패스 남은 일수, 1회 상품 구매 여부, 첫 구매 2배 사용 여부 = 상점 상태(`shop.*`) 그대로. 패스의 "매일 받기"가 주는 물건만 `grant()`로 들어온다.

## 2. 저장 형태

지금 저장 키 `gemGuardians.save.v1` 안에 `inv` 묶음 하나를 추가하고 저장 버전을 올린다(`saveVersion: 2`). 기존 필드는 처음 불러올 때 한 번 옮긴다(마이그레이션).

```json
"inv": {
  "items":   { "hammer": 3, "scythe_h": 3, "revive": 1 },
  "loadout": {
    "hotbar":  ["hammer", "scythe_h", null, null],
    "pendingHotbar": null,
    "preFloor": { "booster_line": true, "booster_bomb": false, "gold_coin": false },
    "totems":  []
  },
  "perm": {
    "skills":  { "red": 1, "blue": 1, "yellow": 1, "green": 1, "purple": 1, "spike": 1, "meteor": 0, "souls": 0, "ultimate": 0 },
    "flags":   ["slot4"],
    "totems":  {}
  },
  "grantedTx": ["iap:starter:GPA.1234", "boss:20"],
  "log": [ { "t": 1762500000, "src": "shopGold", "d": { "hammer": 5, "gold": -1200 } } ],
  "seenItems": ["hammer", "scythe_h"]
}
```

- `hotbar`는 항상 길이 4. 4번째 칸은 `perm.flags`에 `slot4`가 없으면 잠김(값은 null 유지).
- `perm.skills` 값 0 = 미해금, 1~5 = 레벨. 색 효과 5개는 기본 1(처음부터 해금).
- `grantedTx` = 한 번만 받아야 하는 지급의 고유 id(결제 영수증, 보스 첫 처치 보상, 1회 패키지). 같은 id가 다시 오면 무시 → **중복 지급 방지**.
- `log` = 최근 50건만(넘으면 앞에서 버림). 버그 추적·고객 문의용. 개발 패널에서 볼 수 있게.
- 모르는 아이템 id(나중에 지운 아이템 등)는 지우지 말고 그대로 둔다. 화면에만 안 보인다.
- `seenItems` = 메뉴 보관함을 마지막으로 열었을 때 갖고 있던 아이템 id(빨간 점 ①, 5-3). 옛 저장엔 없어 빈 배열로 시작 → 처음 한 번은 점이 뜬다.

### 마이그레이션 (v1 → v2)

| 기존 필드 (아이템/상점 프롬프트가 만든 것) | 옮길 곳 |
|---|---|
| `items` | `inv.items` |
| `equipped` | `inv.loadout.hotbar` (길이 4로 맞춤) |
| 다음 층 예약 필드(이름은 코드 확인) | `inv.loadout.preFloor` |
| `slot4Unlocked` 류 | `inv.perm.flags`에 `slot4` |
| `shop.skillLv` | `inv.perm.skills` |
| 보스 보상 받은 기록 류 | `inv.grantedTx`에 `boss:{층}` |

옮긴 뒤 옛 필드는 삭제. 마이그레이션은 여러 번 돌아도 결과가 같아야 한다(이미 v2면 아무것도 안 함).

## 3. 모듈과 API

새 파일 `src/game/inventory.js`(저장·상태) + 순수 계산은 `src/core/inventory/` (브라우저 API 없이 테스트 가능하게). playerState가 inventory를 하나 갖고, 저장은 playerState.save() 한 번으로.

**읽기**
- `count(id)` / `has(id, n=1)`
- `skillLevel(key)` → 0~5, `isUnlocked(flag)` → slot4, adFree 등
- `hotbar()` → 길이 3 또는 4 배열(잠긴 칸 제외), `slotCount()`
- `visibleItems(bestFloor)` → unlockFloor 안 된 아이템(해제 부적 21층 전)은 제외. **개수는 보존**
- `reservations()` → 켜 둔 다음 층 예약 목록

**쓰기 (전부 이 함수들로만)**
- `grant(bundle, { src, txId? })` → 지급. `bundle = { gold?, diamonds?, items?: {id:n}, skills?: {key: 레벨 또는 '+1'}, flags?: [] }`. `txId`가 이미 `grantedTx`에 있으면 아무것도 안 하고 `{ ok:false, reason:'duplicate' }`. 성공하면 log 1줄 + 변경 이벤트 + 저장.
- `spend(id, n, { src })` → 부족하면 `{ ok:false, reason:'noStock' }` (일부만 빼지 않음)
- `buy({ cost: {gold|diamonds}, bundle, src, txId? })` → 재화 확인 → 차감 + grant를 **한 번에**(중간 실패 시 아무것도 안 바뀜). 상점 골드/다이아 구매는 전부 이걸로.
- `equip(slot, id)` / `unequip(slot)` / `swapSlots(a, b)`
- `setReserve(id, on)` / `consumeReservations()` (층이 실제로 시작될 때만 호출)
- `onChange(fn)` → HUD, 하단 바, 상점 카드가 구독해서 다시 그림

**결과 형태는 아이템 컨트롤러와 같게** `{ ok, reason }`. reason: `noStock`, `noMoney`, `duplicate`, `locked`, `cap`, `notEquipable`, `alreadyEquipped`, `inFloor`.

## 4. 규칙

### 장착
1. 하단 슬롯에는 `group: hotbar` 아이템만. 부스터·황금 주화(preFloor)와 부활(onFail)은 못 꽂음(`notEquipable`).
2. 같은 아이템 두 칸 금지. 이미 꽂힌 걸 다른 칸에 꽂으면 **두 칸이 자리를 바꾼다**(거절보다 편함).
3. 개수가 0이 돼도 **장착은 유지**(슬롯 회색). 상점에서 사면 바로 다시 쓸 수 있게.
4. **층 진행 중 장착 변경 = 다음 층부터 적용.** 인벤토리 탭에서 바꾸면 `pendingHotbar`에 저장하고 "다음 층부터 적용" 표시. 층 시작 때 `hotbar`로 옮김. 지금 층의 하단 바·쿨다운은 그대로(쿨다운 꼼수 방지). 메뉴·층 클리어 화면·패배 팝업에서는 즉시 적용.
5. 처음 시작(장착이 비어 있음) 때 자동 장착: 망치, 가로 낫, 수리 망치. 이후 새 아이템을 처음 얻었고 빈 칸이 있으면 그 칸에 자동 장착.
6. 4번째 슬롯: 20층 보스 첫 처치 **또는** 4번째 슬롯 팩/다이아 구매 → `perm.flags`에 `slot4`. 이미 있으면 팩은 상점에서 숨김, 20층 보스 때도 중복 없음.

### 다음 층 예약
7. 부스터 라인·부스터 폭탄·황금 주화 각각 켜기/끄기, 각 1개, 층당 1회(기존 규칙 유지).
8. 켤 때 개수 확인만, **소모는 층이 실제로 시작될 때**(메뉴로 나가거나 재도전을 안 누르면 소모 없음). 소모 순간 개수가 0이면 그 예약은 꺼짐.

### 지급·개수
9. 아이템 개수 상한 **999**. 넘는 지급은 999에서 멈추고 log에 남김. 상점은 구매 수량을 상한까지만 고를 수 있게.
10. 해제 부적(unlockFloor 21)은 21층 전엔 목록·상점·보상 풀에서 숨기되, 패키지 등으로 들어온 개수는 보존.
11. 젬 스킬: 해금 = 0→1, 레벨업 = +1, 최대 5. 해금 조건(A안: 가시 처음부터, 용암탄 10층·영혼 불꽃 20층·궁극기 30층 보스 첫 처치 후 골드)은 상점이 확인하고 `buy()`로 `skills: { meteor: '+1' }` 지급.
12. 전투는 `skillLevel()`만 읽는다. **레벨 1 = 지금 config 값 그대로**(시뮬레이터 기준 불변). 밸런스 숫자는 이번 작업에서 안 건드림.

### 지급 출처 (src 이름)

| src | 언제 | txId |
|---|---|---|
| `start` | 첫 실행 임시 지급(상점 전 단계 값) | `start` |
| `bossReward` | 보스 첫 처치 아이템 2종 | `boss:{층}` |
| `floorUnlock` | 21층 도달 시 해제 부적 3개 | `unlock:defuse` |
| `shopGold` / `shopDia` | 골드·다이아 구매 | 없음(반복 구매) |
| `iap` | 현금 결제 패키지·다이아 | `iap:{상품}:{영수증 id}` |
| `pass` | 주간·월간 패스 매일 받기 | `pass:{종류}:{날짜}` |
| `freeDaily` | 상점 "오늘의 무료 1개" | `free:{날짜}` |
| `dev` | 개발 패널 +5 | 없음 |
| (나중) `attendance`, `event`, `mail` | 출석·이벤트·우편함 | `att:{날짜}` 등 |

결제는 **스토어 결제 성공 → `grant(..., {txId})` → 저장** 순서. 앱이 중간에 꺼져도 다음 실행 때 미지급 결제를 다시 grant하면 txId 덕분에 두 번 들어가지 않는다(Capacitor 단계에서 스토어의 미완료 거래 조회와 연결).

## 5. 화면 (새 그림 없이 기존 UI 팩으로)

### 5-1. 보관함 화면 (메뉴 받침대 / 탑 강화 팝업 `인벤토리` 탭, 시안 `mockups/inventory.html` B)
같은 그리기(`src/render/inventoryTab.js`)를 두 곳이 쓴다. 위에서 아래로, 구역마다 ui/menu/inset 상자:

```
┌ 장착 칸 ─────────── 2/3 · 길게 누르면 해제 ┐  (층 진행 중이면 "다음 층부터 적용")
│ [가로낫 2] [망치 3] [ + ]  [🔒]              │
│  가로 낫    망치    빈 칸   20층 보스          │
├ 다음 층 예약 ──────────── 층 시작 때 1개 사용 ┤
│ [라인 2] [폭탄 0] [주화 1]  이름 + 예약됨/끔   │
├ [전체][보드][전투][기타] ────────────────────┤
│ 보유 격자(칸 간격 6, 폭에 맞는 열, 빈 칸 틀), 넘치면 스크롤│  장착된 것 = 금색 E
├ 설명 패널(고정) ──────────────────────────────┤
│ [큰 칸 x3] 이름(금) / 설명 2줄 / 수치 칩      │
│ [장착|해제|상점에서 사기]  [상점 가기]         │
└──────────────────────────────────────────────┘
```

- 조작: 보유 아이템 탭 → `장착`(첫 빈 칸). 빈 칸이 없으면 버튼 대신 "장착 칸을 눌러 바꾸기" - 고른 채로 장착 칸을 탭하면 그 칸에(기존 방식). 장착 칸 길게 = 해제. 보유 목록은 끌거나 휠로 스크롤, 끌지 않고 뗄 때 선택.
- 0개: 아이콘은 #3b3347 실루엣(외곽선 유지), 개수 0은 빨강. 개수 숫자 뒤엔 #0d0a10 바탕.
- 분류 탭은 열 때마다 `전체`. 층 진행 중 바꾼 칸(pending)은 slot_selected.
- 칸은 22x22 x2(44px), 설명 패널 큰 칸만 x3(66px, 아이콘 42px). 탭·버튼은 그림보다 터치 영역을 넓혀 44px.
- 팝업은 화면 거의 전체(540x960 기준 좌우 12, 위 96, 아래 48 여백), 엠블럼 자리는 비워 둠(전용 그림 예정). 강화 팝업 인벤토리 탭을 누르면 같은 팝업이 강화 팝업 위에 뜨고(층 진행 중 표시 유지), 닫으면 강화 팝업으로 돌아간다.
- 설명 패널 버튼은 최대 2개, 상점으로 가는 버튼은 하나: 보유+미장착 = 장착/상점 가기, 보유+장착 = 해제/상점 가기, 0개+미장착 = 상점에서 사기, 0개+장착 = 상점에서 사기/해제, 예약·부활 = 상점 가기(0개면 상점에서 사기).

### 5-2. 다른 화면에서 보이는 것
- **하단 바**(전투 중): `hotbar()`와 `count()`만 읽음. 장착 변경 불가.
- **상점 카드**: `보유 n`, 젬 스킬 `Lv n/5`, 구매 후 `onChange`로 바로 갱신.
- **패배 팝업**: 부활(개수 표시) + 다음 층 예약 줄(기존 그대로).
- **획득 팝업(공통, 새로)**: `grant()` 결과 번들을 아이콘 줄로 보여 줌. 보스 보상·패키지·패스·무료 1개가 전부 이 팝업 하나를 씀. 틀은 `ui/menu/popup_menu`.

### 5-3. 메뉴의 보관함 = 신단 받침대
메뉴에 따로 버튼 없이 **신단 받침대를 누르면 보관함**이 열린다(assets/menu/manifest.json `altarInventory`).
- 누르는 영역: `hitArea_screenPx` [174,510,192,174](받침대 윗판~계단 + 이름판, 540x960 기준). 떠 있는 결정 자리(`crystalReserved_screenPx`)는 나중에 다른 메뉴용이라 비워 둔다.
- 누르는 동안 이름판만 1px 아래로, 영역 안에서 떼면 바로 열림, 밖으로 끌고 나가서 떼면 취소. 따로 연출 없음.
- 이름판 "보관함"(`menu.inventory`) 오른쪽 위 빨간 점: ① 보관함을 연 뒤로 처음 가진 아이템이 있을 때(`inv.seenItems`에 없는 보유 1개 이상 아이템), ② 빈 장착 칸이 있고 거기 넣을 수 있는 아이템이 1개 이상일 때. 보관함을 열면 ①은 꺼진다.
- 보관함 화면 = 5-1 인벤토리 탭 내용 그대로(메뉴 팝업 틀). 층 밖이라 장착은 바로 적용, "다음 층부터 적용" 줄 없음. "상점 가기" → 상점, 닫으면 보관함으로 돌아온다.
- 받침대 평소 반복 조각(`altarInventory.idle`)은 배경 조각과 같은 시계로 그린다.

## 6. 나중에 붙일 것 (자리만 마련)

- **토템**: `perm.totems { id: { lv } }` + `loadout.totems` (슬롯 0/2). 지금은 빈 값, 로직 없음.
- **우편함**: 서버/이벤트 보상을 바로 넣지 않고 받기 버튼으로. `grant(..., {src:'mail', txId})` 재사용.
- **클라우드 저장·경쟁 모드**: 경쟁 모드에서는 인벤토리를 서버가 확인해야 함(로컬 저장은 조작 가능). 지금 API를 그대로 두고 저장소만 바꿀 수 있게 `storage` 인터페이스 유지.
- **구매 복원**: 4번째 슬롯·광고 제거 같은 비소모 상품은 스토어 복원 시 `perm.flags`를 다시 세움.
