## 1. 한 줄 요약

메인 메뉴 가운데 **봉인 원석**을 누르면 랭킹 팝업이 뜬다. 탭은 `일반 모드`(최고 도달 층 순)와 `경쟁 모드`(이번 주 포인트 순, 매주 월요일 0시 초기화, 순위 보상). 처음에는 **서버 없이 로컬**(내 기록 + 가짜 순위표)로 만들고, 랭킹 서비스 인터페이스만 맞춰 두었다가 나중에 서버로 바꾼다.

## 2. 진입

- 메뉴 가운데 떠 있는 봉인 원석 터치 영역 = 이미 비워 둔 **crystal reserved [204,270,132,234]** (540x960 화면 px). 받침대(보관함) 영역 [174,510,192,174]과 겹치지 않음.
- 원석은 지금 메뉴 배경 애니 그대로. 누를 수 있다는 표시로 **원석 아래에 작은 이름판**(보관함 `ui/menu/plate`와 같은 모양, 글자 `랭킹`)을 두고, 받을 보상이 있으면 이름판에 `menu/badge` 빨간 점.
- 누르면 `ui_click` + 원석이 잠깐 밝아지는 효과(1~2프레임, 새 그림은 ②단계에서 결정) → 팝업.

## 3. 팝업 틀

- 보관함 팝업과 같은 크기·틀: 540x960 기준 **x12 y96 w516 h816**, 뒤 배경막은 #0d0a10 디더.
- 위: 문장(새로 그릴 `emblem_rank` 24x24, 목업에선 `emblem_win` 왕관 임시) + 제목 `랭킹` + 닫기 X.
- 탭 2개: `일반 모드` | `경쟁 모드` (`upgrade/tab_on`·`tab_off`·`tab_body`). 처음 열 때는 **마지막으로 본 탭**, 처음이면 일반 모드. 경쟁 모드가 잠겨 있으면 탭에 자물쇠 + 눌렀을 때 해금 조건 안내(내용은 볼 수 있게 할지 §9-3).
- 맨 아래 고정: **내 순위 줄**(목록을 아무리 내려도 항상 보임). 내가 화면 안에 있으면 목록 속 내 줄을 금테로 강조.

## 5. 경쟁 모드 탭

### 5-1. 시즌

- **매주 월요일 00:00 KST**(= 일요일 15:00 UTC)에 초기화. 한국은 서머타임이 없어서 UTC+9 고정으로 계산하면 됨.
- 시즌 id = KST 기준 ISO 주차 `2026-W45`. 위쪽 머리글에 `45주차 시즌 · 종료까지 2일 13:20:05` 타이머.
- 종료 **10분 전부터 `정산 대기`** 표시(순위는 보이고, 이 시간에 끝난 판도 이번 시즌에 들어감). 서버 단계에서는 종료 후 정산이 끝날 때까지 `정산 중`.
- **판이 시즌 경계를 넘으면**: 판을 시작할 때의 시즌에 점수를 넣는다(시작할 때 seasonId를 저장).

### 5-2. 포인트 (경쟁 모드 규칙이 정해지기 전 가정)

랭킹 쪽은 "판이 끝나면 포인트 하나를 받는다"만 알면 된다. 포인트 계산은 경쟁 모드 기획에서 정하고, 지금은 목업용으로 이렇게 가정:

- 랭킹 점수 = **이번 주 최고 1판 점수** (누적 아님). 누적이면 오래 하는 사람·결제한 사람이 유리해져서 경쟁 의미가 약해짐. 누적이 좋으면 §9-1에서 바꿈.
- 1판 점수(예시) = 처치 점수(일반 10 / 정예 50 / 보스 300) × (1 + 층/10) + 층 클리어 100 × 층 + 남은 성벽 HP 보너스.
- 동점: 그 점수를 **먼저 낸 사람**이 위.
- 한 줄: 순위 · 대표 석상 · 닉네임 · `12,480 P` · 작은 글씨 `34층`.

### 5-3. 보상 구간 (UI에 들어가는 자리)

목록에서 **보상 구간이 바뀌는 곳마다 얇은 구분 줄**(`── 상위 10% · 다이아 60 ──`)을 넣어서 "조금만 더 올리면 다음 구간"이 보이게 한다. 머리글에는 내 현재 구간 배지 + `다음 구간까지 320 P`.

| 구간 | 기준 | 보상 (예시, 임시) | 칭호·테두리 |
|---|---|---|---|
| 1위 | 순위 | 다이아 500 + 무지개 결정 5 | `주간 수호왕` 칭호 + 금 왕관 테두리 (다음 시즌 동안) |
| 2위 | 순위 | 다이아 400 + 무지개 결정 3 | 은 왕관 테두리 |
| 3위 | 순위 | 다이아 300 + 무지개 결정 2 | 동 왕관 테두리 |
| 4~10위 | 순위 | 다이아 200 + 부활 1 | 금 테두리 |
| 11~50위 | 순위 | 다이아 150 | — |
| 상위 1% | 비율 | 다이아 120 | — |
| 상위 5% | 비율 | 다이아 80 | — |
| 상위 10% | 비율 | 다이아 60 | — |
| 상위 30% | 비율 | 다이아 40 | — |
| 상위 50% | 비율 | 다이아 25 | — |
| 참여 | 1판 이상, 점수 > 0 | 다이아 10 + 골드 (최고 층 일반 층 3개 분량) | — |

- 순위 구간과 비율 구간이 겹치면 **더 좋은 쪽 하나만**.
- 기준 가격: 다이아 60 = ₩1,200 (상점 목업). 1위 500 ≈ ₩10,000 가치. 숫자는 밸런스 때 다시 정함.
- 보상 탭이 아니라 **경쟁 탭 안의 `보상 보기` 버튼 → 작은 팝업**으로 표 전체. 탭을 하나 더 만들면 팝업이 복잡해짐.

### 5-4. 지난 시즌 결과

- 초기화 후 처음 메뉴에 들어오면(또는 랭킹을 열면) **시즌 결과 팝업**: `44주차 시즌 결과 · 128위 · 상위 7%` + 구간 배지 + 보상 아이콘 + `받기`.
- 받기 = 인벤토리 `grant` (txId `rank:2026-W44`로 한 번만). 받기 전까지 메뉴 이름판에 빨간 점.
- 경쟁 탭 맨 위에 `지난 시즌 128위` 한 줄(눌러서 최근 8주 기록).

## 6. 프로필 (닉네임·대표 석상)

- 랭킹을 **처음 열 때** 닉네임 입력 팝업: 2~10자, 한글·영문·숫자, 중복 확인은 서버 단계부터. 나중에 바꾸기는 랭킹 팝업 내 줄의 연필 버튼.
- 대표 석상: 5색 석상 중 하나(기본 = 가장 레벨 높은 석상). 새 그림 없이 `assets/statues/*.png` 사용.
- 금칙어 필터는 서버 단계에서.

## 7. 데이터

### 7-1. 저장 (save에 추가, saveVersion 올림)

```js
ranking: {
  profile: { playerId: 'uuid', nickname: '', statue: 'red' },
  normal: { bestFloor: 0, reachedAt: 0 },          // ms
  comp: {
    seasonId: '2026-W45',
    best: { points: 0, floor: 0, at: 0 },          // 이번 주 최고 1판
    runs: 0,
    pending: null,  // { seasonId, rank, pct, tierId, rewards:[...] } 받기 전
    history: []     // 최근 8개 { seasonId, points, rank, pct, tierId }
  },
  lastTab: 'normal'
}
```

### 7-2. 순위표 한 줄 (서비스가 돌려주는 모양)

```js
{ playerId, nickname, statue, value, sub /* 층 */, at, rank, frame /* 'gold'|'silver'|'bronze'|'crown_gold'|null */ }
```

### 7-3. 랭킹 서비스 인터페이스

```js
RankingService = {
  submit(mode, { value, floor, at, seasonId, runLog? }),   // 판 끝날 때
  top(mode, { seasonId, limit: 100 }) -> entries[],
  me(mode, { seasonId }) -> { rank, pct, value, tierId },
  settle(seasonId) -> { rank, pct, tierId, rewards }        // 지난 시즌 결과
}
```

- **LocalRankingService** (지금): 내 기록은 save에서, 다른 사람은 **시즌 id를 씨앗으로 만든 가짜 200명**(닉네임·점수 분포 고정). 개발·목업용이라 설정 `config/ranking.json`의 `fakeBoard: true`일 때만. 보상도 가짜 순위로 계산해서 흐름 전체를 시험할 수 있게.
- **ServerRankingService** (나중): 같은 함수 그대로. 바꾸는 곳은 서비스 1개.
- 시즌 계산·보상 구간 표는 `config/ranking.json`에 (`resetDay: 1, resetHourKst: 0, tiers: [...]`).

## 8. 서버 단계 (나중, 메모만)

- 로컬 저장은 고칠 수 있으니 **실제 보상은 서버 단계부터**. 로컬 단계 출시라면 경쟁 탭은 `준비 중`으로 잠그고 일반 탭만 내 기록 + (앱 단계) Google Play Games / Game Center 리더보드로 보여주는 방법도 있음.
- 후보: Firebase(Firestore + Cloud Functions 예약 실행으로 월요일 정산) 또는 Supabase(Postgres + cron). 둘 다 무료 구간으로 시작 가능.
- 점수 검증: 경쟁 모드를 **주간 고정 시드**로 만들면 서버가 판 기록(runLog: 시드 + 교환 순서)으로 다시 계산해 볼 수 있음. 최소한 층·시간 대비 점수 상한 검사.
- 인벤토리 기획대로 경쟁 모드 보상·아이템은 서버가 확인.

## 13. 서버 설계 (구현 X, 설계만)

### 13-1. 고르는 기준과 추천

| 후보 | 장점 | 단점 |
|---|---|---|
| **Firebase** (Auth 익명 + Firestore + Cloud Functions + Cloud Scheduler) | Capacitor 플러그인 있음, 익명 로그인 → 나중에 Google/Apple 계정 연결, 예약 함수로 월요일 정산 | Firestore는 "내 순위 몇 위"(count 쿼리) 비용이 큼 → 정산 때 순위를 미리 계산해 둬야 함 |
| Supabase (Postgres + Edge Functions + pg_cron) | SQL `rank()` 한 줄로 순위·비율 계산, 백분위 쉬움 | Capacitor 쪽 인증 연결은 직접 |
| Play Games / Game Center 리더보드 | 무료, 주간 리더보드 기본 제공 | 보상 지급·검증은 못 함, 두 플랫폼 따로 |

추천: **Supabase** (순위·비율 계산이 이 기능의 핵심이라 SQL이 편함). Firebase를 이미 쓰게 되면(푸시·분석) Firebase로 해도 되고, 그때는 정산 함수가 순위를 미리 써 두는 방식.

### 13-2. 테이블 (Supabase 기준)

```sql
players  (player_id uuid pk, nickname text unique, statue text, created_at, banned bool)
normal_best (player_id pk, best_floor int, reached_at timestamptz)
comp_best   (season_id text, player_id, points int, floor int, at timestamptz, run_hash text,
             primary key (season_id, player_id))
comp_runs   (run_id uuid pk, season_id, player_id, seed bigint, points int, floor int,
             started_at, ended_at, log jsonb, verified bool)          -- 검증용 원본
season_results (season_id, player_id, rank int, pct numeric, tier_id text,
                rewards jsonb, claimed_at timestamptz, primary key (season_id, player_id))
```

순위 = `order by best_floor desc, reached_at asc` / `order by points desc, at asc`.

### 13-3. API (클라이언트 `ServerRankingService`가 부를 것)

| 호출 | 하는 일 |
|---|---|
| `POST /rank/profile` {nickname, statue} | 닉네임 중복·금칙어 검사 후 저장 |
| `POST /rank/normal` {floor, at} | 더 높을 때만 갱신 (서버가 이전 값과 비교) |
| `POST /rank/comp/start` → {runId, seasonId, seed} | 서버가 시즌·시드 정해 줌 (시즌 경계 문제 해결) |
| `POST /rank/comp/finish` {runId, points, floor, log} | 점수 상한 검사 → comp_best 갱신, 이상하면 verified=false로 보류 |
| `GET /rank/top?mode&season&limit=100` | 1~100위 (60초 캐시) |
| `GET /rank/me?mode&season` | 내 순위·비율·구간·다음 구간까지 |
| `GET /rank/result?season` | 지난 시즌 결과 + 받기 전 보상 |
| `POST /rank/claim` {seasonId} | 보상 지급 기록 (한 번만), 클라이언트는 `grant(txId rank:{seasonId})` |

### 13-4. 정산

- 매주 **월요일 00:00 KST** = 일요일 15:00 UTC에 cron → 그 시즌 `comp_best`를 순위 매겨 `season_results`에 기록(구간·보상은 `config/ranking.json`과 같은 표를 서버에 복사).
- 정산 동안(보통 몇 초~몇 분) `GET /rank/top`은 `settling: true` → 화면에 `정산 중`.
- 종료 전 시작한 판은 `start` 때 받은 seasonId로 끝까지 계산. 종료 후 **30분까지만** 받아 줌.
- 결과 보관 8주, 끝난 시즌 `comp_runs.log`는 4주 후 삭제.

### 13-5. 부정 방지 (단계별)

1. 점수 상한: 층·걸린 시간 대비 최대 점수 표를 넘으면 보류.
2. 경쟁 모드를 **주간 고정 시드**로 하면 서버가 log(교환 순서·시각)로 다시 계산해 볼 수 있음(같은 퍼즐 코어를 서버에서 돌림). 1위~50위만 검증해도 충분.
3. 계정당 1기기 동시 로그인, 정산 전 수동 확인 대상 표시(1~10위).

### 13-6. 클라이언트에서 바뀌는 것

`RankingService` 하나만 `Local → Server`로 바꿈. 오프라인이면 마지막으로 받은 순위표를 보여 주고 `오프라인 · 마지막 갱신 3분 전` 한 줄. 판 결과 제출은 큐에 쌓았다가 연결되면 보냄(같은 runId는 한 번만).
