## 1. 한 줄 요약

메인 메뉴 가운데 **봉인 원석**을 누르면 랭킹 팝업이 뜬다. 탭은 `일반 모드`(최고 도달 층 순)와 `경쟁 모드`(이번 주 포인트 순, 매주 월요일 0시 초기화, 순위 보상). 처음에는 **서버 없이 로컬**(내 기록 + 가짜 순위표)로 만들고, 랭킹 서비스 인터페이스만 맞춰 두었다가 나중에 서버로 바꾼다.

## 2. 진입

- 메뉴 가운데 떠 있는 봉인 원석 터치 영역 = 이미 비워 둔 **crystal reserved [204,270,132,234]** (540x960 화면 px). 받침대(보관함) 영역 [174,510,192,174]과 겹치지 않음.
- 원석은 지금 메뉴 배경 애니 그대로. 누를 수 있다는 표시로 **원석 아래에 작은 이름판**(보관함 `ui/menu/plate`와 같은 모양, 글자 `랭킹`)을 두고, 받을 보상이 있으면 이름판에 `menu/badge` 빨간 점.
- 누르면 `ui_click` + 원석이 잠깐 밝아지는 효과(1~2프레임, 새 그림은 ②단계에서 결정) → 팝업.

## 3. 팝업 틀

- 보관함 팝업과 같은 크기·틀: 540x960 기준 **x12 y96 w516 h816**, 뒤 배경막은 #0d0a10 디더.
- 위: 문장(새로 그릴 `emblem_rank` 24x24, 목업에선 `emblem_win` 왕관 임시) + 제목 `랭킹` + 닫기 X.
- 탭 2개: `일반 모드` | `경쟁 모드` (`upgrade/tab_on`·`tab_off`·`tab_body`). 처음 열 때는 **마지막으로 본 탭**, 처음이면 일반 모드. 경쟁 모드가 잠겨 있으면 탭에 자물쇠 + 눌렀을 때 해금 조건 안내(내용은 볼 수 있게 할지 §9-3).
- 맨 아래 고정: **내 순위 줄**(목록을 아무리 내려도 항상 보임). 내가 화면 안에 있으면 목록 속 내 줄을 금테로 강조.

## 5. 경쟁 모드 탭

### 5-1. 시즌

- **매주 월요일 00:00 KST**(= 일요일 15:00 UTC)에 초기화. 한국은 서머타임이 없어서 UTC+9 고정으로 계산하면 됨.
- 시즌 id = KST 기준 ISO 주차 `2026-W45`. 위쪽 머리글에 `45주차 시즌 · 종료까지 2일 13:20:05` 타이머.
- 종료 **10분 전부터 `정산 대기`** 표시(순위는 보이고, 이 시간에 끝난 판도 이번 시즌에 들어감). 서버 단계에서는 종료 후 정산이 끝날 때까지 `정산 중`.
- **판이 시즌 경계를 넘으면**: 판을 시작할 때의 시즌에 점수를 넣는다(시작할 때 seasonId를 저장).

### 5-2. 판 규칙과 점수 (확정 2026-11-23)

경쟁 모드 한 판 = **무한 웨이브**. 1층부터 올라가는 층 대신, 성벽이 무너질 때까지 점점 강해지는 웨이브가 끝없이 온다.
코드: 웨이브·점수·입력 기록 `src/core/comp/endless.js`, 전투 이어 붙이기 `battleState.nextWave`, 판 상태 `BattleController.startComp`,
화면·서버 연결 `src/main.js`(compStatus / startCompGame / endCompRun). 수치는 전부 `config/ranking.json` `comp`(서버 사본 `_shared/ranking.json`).

| # | 규칙 | 내용 | config |
|---|---|---|---|
| 1 | 시드 | **주간 고정 시드**. 시즌(월 00:00 KST)마다 서버가 `md5('comp:'+시즌)`으로 정하고 `rank-comp-start`가 내려준다. 퍼즐 보드·웨이브 구성(적 뽑기·순서·무리)이 모두 이 시드에서만 나온다(Math.random 없음). 같은 주 = 모두 같은 보드·웨이브. | - |
| 2 | 입력 기록 | 판 동안 스왑 `[ms, r1, c1, r2, c2]`·아이템 `[ms, id, target]`을 남겨 점수와 함께 `rank-comp-finish`의 `log`로 보낸다(시각 = 판 시계). 2500개에서 자르고 `truncated`. 지금은 **저장만**(4주 보관). 서버 재계산은 **출시 뒤로 미룸(2026-11-27)**: 전투가 프레임 시간(가변 dt)으로 돌아 ms 기록만으로는 같은 판이 다시 나오지 않는다 - 하려면 전투·보드를 고정 간격으로 바꾸고 기록도 그 단위로 남겨야 하며, 한 판(약 10분 분량)을 서버 함수 시간 한도 안에 돌릴 수 있는지도 봐야 한다. 그때까지 = 점수 상한 + 정산(월 00:31 KST) 전에 상위권을 눈으로 보고 이상하면 관리자 페이지 "랭킹 숨김"(숨긴 계정은 `comp_board`에서 빠져 순위·보상 모두 제외). | - |
| 3 | 시작 조건 | 본편 성장과 무관하게 석상 5개 모두 **Lv20**, 색 효과·특수 기술 4종 모두 **해금 Lv1 고정**. 판 중 골드 획득·석상 강화 없음. 정령·광산 보너스 없음(둘 다 전투 버프가 없어 막을 것도 없음). | `towerLevel` `skillLevel` |
| 4 | 아이템 | 가방·상점 아이템 사용 불가, 부스터·황금 주화 예약도 소모 안 함. 매 판 같은 **키트**(망치 2, 낫 1)를 하단 바에 지급하고, 판이 끝나면 남은 키트는 사라진다. | `kit` |
| 5 | 진행 | 웨이브 1부터 성벽이 0이 될 때까지. 웨이브 사이에 성벽은 초기화되지 않고 **회복도 없다**(`wallHealPct` 0, 2026-11-23). **이어하기(깃털·광고) 없음**. | `endless` |
| 6 | 입장 | **하루 3회 무료**(KST 자정 초기화, 이월 없음). 다이아·광고로 추가 입장 불가. 서버가 `comp_runs`로 센다(`comp_start`가 넘으면 `dailyLimit`). 판을 시작하면 끝내지 않아도 1회. | `dailyEntries` |

| 8 | 주간 변주 | 시즌별 modifier 하나(예: 빨강 보석 피해 2배)를 넣을 자리만 있다 - `rank-comp-start` 응답 `modifier`(기본 null). **게임 적용 코드는 아직 없음.** | `modifier` |

**무한 웨이브** - 웨이브 n = 층 생성기(`genFloor`)의 "난이도 층" 하나 분량의 적(주간 시드로 섞음):
- 난이도 층 = `startFloor`(15) + (n-1) × `floorsPerWave`(1), **웨이브 10부터 웨이브마다 +2층**(`rampFrom` 10, `rampMul` 2). 웨이브 1 = 15층, 웨이브 10 = 24층, 웨이브 11 = 26층, 웨이브 17 = 38층.
- 보스(난이도 층이 10의 배수)는 HP × `bossHpMul`(0.4). 1배면 Lv20으로 20층 보스가 넘을 수 없는 벽이라 보통 플레이어 10판이 모두 같은 자리(20층 보스)에서 끝났다 - 순위가 실력보다 처치 점수로만 갈림.
- 난이도 층이 101 이상(49웨이브 이후)이면 보스 HP 배율도 일반 모드와 같은 `floorGen.bossHpMulAt` 규칙(같은 자리 값 × cycleMul, docs/balance.md 11장)을 따른다(`bossHpMul` 0.4는 그 위에 곱함).
- 앞 웨이브를 다 소환하고 `waveGapSec`(3초) 뒤 다음 웨이브가 이어진다. 웨이브 수 = 실제로 나오기 시작한 웨이브.
- 방해요소는 웨이브 1(난이도 15층)의 설정을 판 내내 쓴다.
- 수치는 시뮬 T8로 정했다(`tools/sim/tests/t8.js`, docs/simulation.md T8). 시드 30개, 석상 Lv20, 키트 사용:

| 플레이어 | 판 길이 중앙(P10~P90) | 도달 웨이브 | 점수 중앙 |
|---|---|---|---|
| fast | 12.4분 (10.9~15.7) | 27 (24~29) | 48,955 (43,300~53,627) |
| normal | 9.8분 (7.1~14.1) | 17 (14~24) | 29,036 (23,780~42,251) |
| slow | 9.2분 (4.7~10.4) | 14 (7~15) | 23,586 (11,240~24,954) |
| worst(참고) | 5.4분 (2.3~6.8) | 7 (3~7) | 10,946 (4,488~11,668) |

  성벽 회복 0(지금 값). 회복 0.2일 때와 비교: 도달 웨이브는 같고, fast 판 길이 14.2 → 12.4분, 점수는 각 플레이어 1% 안쪽으로 낮아짐(성벽 보너스가 줄어서). 웨이브가 몰리면 한 번에 무너져서 회복량이 결과를 거의 못 바꾼다.

**점수** = 도달 웨이브 × 1000 + 처치 점수 + 남은 성벽 보너스.
- 처치 점수(역할별, `score.killPoints`): 무리 10, 보병 20, 돌격 20, 탱커 50, 술사 70, 중갑 80, 거한 140, 보스 300. 엘리트 × 5(`eliteMul`). (역할 기본 골드 × 10)
- 남은 성벽 보너스: 새 웨이브가 시작될 때마다 그때(회복 전) 남은 성벽 비율 × 100(`wallBonus`).
- 랭킹 = 이번 주 **최고 1판**. 동점은 그 점수를 **먼저 낸 사람**이 위. 한 줄 표시: `12,480 P` · 작은 글씨 = 도달 웨이브(서버 `floor` 칸에 웨이브를 넣는다).
- 판 화면: 층 배지 = `웨이브 N`(바뀔 때 배너), 보드 위 점수 띠 = **경쟁 점수**(일반 모드의 퍼즐 점수 자리 - 경쟁 판에서는 퍼즐 점수를 안 보여 준다).

**서버 점수 상한**(`_shared/ranking.ts` `compScoreOk`): 웨이브 n까지 Σ(1000 + 100 + 그 웨이브 최대 처치 점수).
- 웨이브별 최대 처치 점수는 시드 100개 중 최대 × 1.25 - 표 `_shared/comp_limits.json`(웨이브 200까지, `node tools/gen_comp_limits.mjs`로 만듦, 표 밖은 마지막 칸 차이로 늘림). config(comp·balance·enemies)를 바꾸면 다시 돌린다(tests/comp.test.js가 표가 최신인지 본다).
- 웨이브 하나에 최소 20초(그보다 빠른 판은 보류, 2026-11-27 5초 → 20초. 시뮬 T8 fast 봇의 가장 빠른 판 = 웨이브당 27.8초, 시간은 서버가 잰 시작~제출이라 불러오기·일시정지만큼 더 여유). 넘으면 기록만 하고 순위에 안 넣는다(verified=false).
- 예: 웨이브 17 상한 39,378, 웨이브 24 상한 57,405(시뮬 normal P90 42,251), 웨이브 29 상한 71,669(시뮬 fast P90 53,627).
- 정산 참여 보상 골드(`goldFloorMul` × 층 기준가)는 `comp_best.floor`(= 도달 웨이브)를 층으로 읽는다 - 그대로 두기로 함(5-4).

**판 흐름**: 메뉴 > 모드 선택 > 경쟁 모드(오늘 남은 입장 표시) → `rank-comp-start`(남은 입장 `left`, 시즌, 시드) → 판 → 패배 팝업 "결과 보기" 또는 일시정지·뒤로가기 "포기하고 나가기" = 그때 점수로 `rank-comp-finish` → 메뉴에서 결과 팝업(점수·웨이브). 본편 층·골드·가방·장착은 그대로. **앱을 강제로 끄면 제출되지 않는다**(입장 1회는 이미 씀).

### 5-3. 보상 구간 (UI에 들어가는 자리)

목록에서 **보상 구간이 바뀌는 곳마다 얇은 구분 줄**(`── 상위 10% · 다이아 60 ──`)을 넣어서 "조금만 더 올리면 다음 구간"이 보이게 한다. 머리글에는 내 현재 구간 배지 + `다음 구간까지 320 P`.

| 구간 | 기준 | 보상 (예시, 임시) | 칭호·테두리 |
|---|---|---|---|
| 1위 | 순위 | 다이아 500 + 무지개 결정 5 | `주간 수호왕` 칭호 + 금 왕관 테두리 (다음 시즌 동안) |
| 2위 | 순위 | 다이아 400 + 무지개 결정 3 | 은 왕관 테두리 |
| 3위 | 순위 | 다이아 300 + 무지개 결정 2 | 동 왕관 테두리 |
| 4~10위 | 순위 | 다이아 200 + 부활 1 | 금 테두리 |
| 11~50위 | 순위 | 다이아 150 | — |
| 상위 1% | 비율 | 다이아 120 | — |
| 상위 5% | 비율 | 다이아 80 | — |
| 상위 10% | 비율 | 다이아 60 | — |
| 상위 30% | 비율 | 다이아 40 | — |
| 상위 50% | 비율 | 다이아 25 | — |
| 참여 | 1판 이상, 점수 > 0 | 다이아 10 + 골드 (최고 층 일반 층 3개 분량) | — |

- 순위 구간과 비율 구간이 겹치면 **더 좋은 쪽 하나만**.
- 기준 가격: 다이아 60 = ₩1,200 (상점 목업). 1위 500 ≈ ₩10,000 가치. 숫자는 밸런스 때 다시 정함.
- 보상 탭이 아니라 **경쟁 탭 안의 `보상 보기` 버튼 → 작은 팝업**으로 표 전체. 탭을 하나 더 만들면 팝업이 복잡해짐.

#### 5-3-1. 출시 기념 기간 (2026-11-28 결정)

참가자가 적을 때는 위 표가 맞지 않는다(100명 미만이면 비율 구간이 전부 순위 구간에 가려져 1~50위 150+, 51위부터 10). 그래서 출시 직후 얼마 동안은:

| 구간 | 보상 |
|---|---|
| 1~3위 | 다이아 100 + 참여 골드(층 기준가 × 3), 왕관 테두리 |
| 그 밖 참여 | 다이아 50 + 참여 골드 |

- `config/ranking.json` `launch.on = true` + `tiers` = 위 표. 위 5-3 표는 `rankedTiers`에 그대로(아직 안 씀).
- 경쟁 모드 시작(모드 팝업 → 경쟁) 때 **하루(KST)에 1번** 안내 팝업(`menu.compLaunch`) - [확인]이면 판 시작, X면 취소. 본 날짜는 save `ranking.launchSeen`.
- `보상 보기` 팝업 아래 안내 줄이 `지금은 출시 기념 기간이에요. 순위별 보상 적용: {시점}`으로 바뀐다.
- 시행일(`launch.rankedFrom`, 'YYYY-MM-DD' KST)은 **아직 미정** - null이면 `추후 공지`로 보인다. 날짜를 넣으면 `M월 D일 시즌부터`.
- 끝낼 때: `tiers` ← `rankedTiers`(그때 확정한 표), `launch.on = false`, 서버 사본(`_shared/ranking.json`)도 같이 배포 - **순위 보상을 처음 주는 주의 정산(월 00:31) 전에**. 앱에 든 표는 앱 업데이트 전까지 옛 표가 보인다.

### 5-4. 지난 시즌 결과

- **보상 = 우편**(2026-11-26 결정). 서버 cron `settle`(일 15:31 UTC = 월 00:31 KST)이 지난 시즌을 정산해 `season_results`에 넣고, 보상이 있는 사람마다 내 우편 1통(`경쟁 모드 44주차 보상 · 128위`, 30일)을 보낸다(`comp_settle_due(tiers, floor_gold, p_mail = rewardsEnabled)`). 받기는 다른 우편과 같은 `mail_claim`(`mail:{id}`) - 우편함 빨간 점이 알려 준다.
- 기기는 정산·지급하지 않는다. 예전 랭킹 팝업 결과 화면·`받기`·랭킹 이름판 빨간 점·`rank_claim`(txId `rank:{시즌}`)은 지웠다.
- 경쟁 탭 맨 위 `지난 시즌 128위`·최근 8주 기록: 지금은 비어 있다(서버 `season_results`를 받아 오는 길이 아직 없음).
- 참여 보상 골드(`goldFloorMul`)의 층 = 그 시즌 최고 판의 **도달 웨이브**(웨이브 N = N층 기준가) 그대로 둔다(2026-11-26 결정).

## 8. 서버 단계 (나중, 메모만)

- 로컬 저장은 고칠 수 있으니 **실제 보상은 서버 단계부터**. 로컬 단계 출시라면 경쟁 탭은 `준비 중`으로 잠그고 일반 탭만 내 기록 + (앱 단계) Google Play Games / Game Center 리더보드로 보여주는 방법도 있음.

- 인벤토리 기획대로 경쟁 모드 보상·아이템은 서버가 확인.

## 13. 서버 설계 (구현 X, 설계만)

### 13-1. 고르는 기준과 추천

| 후보 | 장점 | 단점 |
|---|---|---|
| **Firebase** (Auth 익명 + Firestore + Cloud Functions + Cloud Scheduler) | Capacitor 플러그인 있음, 익명 로그인 → 나중에 Google/Apple 계정 연결, 예약 함수로 월요일 정산 | Firestore는 "내 순위 몇 위"(count 쿼리) 비용이 큼 → 정산 때 순위를 미리 계산해 둬야 함 |
| Supabase (Postgres + Edge Functions + pg_cron) | SQL `rank()` 한 줄로 순위·비율 계산, 백분위 쉬움 | Capacitor 쪽 인증 연결은 직접 |
| Play Games / Game Center 리더보드 | 무료, 주간 리더보드 기본 제공 | 보상 지급·검증은 못 함, 두 플랫폼 따로 |

추천: **Supabase** (순위·비율 계산이 이 기능의 핵심이라 SQL이 편함). Firebase를 이미 쓰게 되면(푸시·분석) Firebase로 해도 되고, 그때는 정산 함수가 순위를 미리 써 두는 방식.

### 13-2. 테이블 (Supabase 기준)

```sql
players  (player_id uuid pk, nickname text unique, statue text, created_at, banned bool)
normal_best (player_id pk, best_floor int, reached_at timestamptz)
comp_best   (season_id text, player_id, points int, floor int, at timestamptz, run_hash text,
             primary key (season_id, player_id))
comp_runs   (run_id uuid pk, season_id, player_id, seed bigint, points int, floor int,
             started_at, ended_at, log jsonb, verified bool)          -- 검증용 원본
season_results (season_id, player_id, rank int, pct numeric, tier_id text,
                rewards jsonb, claimed_at timestamptz, primary key (season_id, player_id))
```

순위 = `order by best_floor desc, reached_at asc` / `order by points desc, at asc`.

### 13-3. API (클라이언트 `ServerRankingService`가 부를 것)

| 호출 | 하는 일 |
|---|---|
| `POST /rank/profile` {nickname, statue} | 닉네임 중복·금칙어 검사 후 저장 |
| `POST /rank/normal` {floor, at} | 더 높을 때만 갱신 (서버가 이전 값과 비교) |
| `POST /rank/comp/start` → {runId, seasonId, seed} | 서버가 시즌·시드 정해 줌 (시즌 경계 문제 해결) |
| `POST /rank/comp/finish` {runId, points, floor, log} | 점수 상한 검사 → comp_best 갱신, 이상하면 verified=false로 보류 |
| `GET /rank/top?mode&season&limit=100` | 1~100위 (60초 캐시) |
| `GET /rank/me?mode&season` | 내 순위·비율·구간·다음 구간까지 |
| (지움) `rank-claim` | 보상은 정산 때 우편으로(5-4) - 받기는 `mail-claim` |

### 13-4. 정산

- 매주 **월요일 00:00 KST** = 일요일 15:00 UTC에 cron → 그 시즌 `comp_best`를 순위 매겨 `season_results`에 기록(구간·보상은 `config/ranking.json`과 같은 표를 서버에 복사).
- 정산 동안(보통 몇 초~몇 분) `GET /rank/top`은 `settling: true` → 화면에 `정산 중`.
- 종료 전 시작한 판은 `start` 때 받은 seasonId로 끝까지 계산. 종료 후 **30분까지만** 받아 줌.
- 결과 보관 8주, 끝난 시즌 `comp_runs.log`는 4주 후 삭제.

### 13-5. 부정 방지 (단계별)

1. 점수 상한: 층·걸린 시간 대비 최대 점수 표를 넘으면 보류.
2. 경쟁 모드를 **주간 고정 시드**로 하면 서버가 log(교환 순서·시각)로 다시 계산해 볼 수 있음(같은 퍼즐 코어를 서버에서 돌림). 1위~50위만 검증해도 충분.
3. 계정당 1기기 동시 로그인, 정산 전 수동 확인 대상 표시(1~10위).

### 13-6. 클라이언트에서 바뀌는 것

`RankingService` 하나만 `Local → Server`로 바꿈. 오프라인이면 마지막으로 받은 순위표를 보여 주고 `오프라인 · 마지막 갱신 3분 전` 한 줄. 판 결과 제출은 큐에 쌓았다가 연결되면 보냄(같은 runId는 한 번만).
